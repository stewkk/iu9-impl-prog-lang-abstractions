<p style="margin-left:18%; margin-top: 1em">The value may
be a simple command name or a command with arguments, and
may use shell quoting (backslashes, single quotes, or double
quotes). It may not use pipes to connect multiple commands;
if you need that, use a wrapper script, which may take the
file to display either as an argument or on standard
input.</p>

<p style="margin-left:9%;"><b>MANLESS</b></p>

<p style="margin-left:18%;">If $<b>MANLESS</b> is set, its
value will be used as the default prompt string for the
<b>less</b> pager, as if it had been passed using the
<b>&minus;r</b> option (so any occurrences of the text
<b>$MAN_PN</b> will be expanded in the same way). For
example, if you want to set the prompt string
unconditionally to &ldquo;my prompt string&rdquo;, set
$<b>MANLESS</b> to
&lsquo;<b>&minus;Psmy&nbsp;prompt&nbsp;string</b>&rsquo;.
Using the <b>&minus;r</b> option overrides this environment
variable.</p>

<p style="margin-left:9%;"><b>BROWSER</b></p>

<p style="margin-left:18%;">If $<b>BROWSER</b> is set, its
value is a colon-delimited list of commands, each of which
in turn is used to try to start a web browser for <b>man
&minus;&minus;html</b>. In each command, <i>%s</i> is
replaced by a filename containing the HTML output from
<b>groff</b>, <i>%%</i> is replaced by a single percent sign
(%), and <i>%c</i> is replaced by a colon (:).</p>

<p style="margin-left:9%;"><b>MANWIDTH</b></p>

<p style="margin-left:18%;">If $<b>MANWIDTH</b> is set, its
value is used as the line length for which manual pages
should be formatted. If it is not set, manual pages will be
formatted with a line length appropriate to the current
terminal (using the value of $<b>COLUMNS</b>, and
<b>ioctl</b>(2) if available, or falling back to 80
characters if neither is available). Cat pages will only be
saved when the default formatting can be used, that is when
the terminal line length is between 66 and 80
characters.</p>

<p style="margin-left:9%;"><b>MAN_KEEP_FORMATTING</b></p>

<p style="margin-left:18%;">Normally, when output is not
being directed to a terminal (such as to a file or a pipe),
formatting characters are discarded to make it easier to
read the result without special tools. However, if
$<b>MAN_KEEP_FORMATTING</b> is set to any non-empty value,
these formatting characters are retained. This may be useful
for wrappers around <b>man</b> that can interpret formatting
characters.</p>

<p style="margin-left:9%;"><b>MAN_KEEP_STDERR</b></p>

<p style="margin-left:18%;">Normally, when output is being
directed to a terminal (usually to a pager), any error
output from the command used to produce formatted versions
of manual pages is discarded to avoid interfering with the
pager&rsquo;s display. Programs such as <b>groff</b> often
produce relatively minor error messages about typographical
problems such as poor alignment, which are unsightly and
generally confusing when displayed along with the manual
page. However, some users want to see them anyway, so, if
$<b>MAN_KEEP_STDERR</b> is set to any non-empty value, error
output will be displayed as usual.</p>

<p style="margin-left:9%;"><b>MAN_DISABLE_SECCOMP</b></p>

<p style="margin-left:18%;">On Linux, <b>man</b> normally
confines subprocesses that handle untrusted data using a
<b>seccomp</b>(2) sandbox. This makes it safer to run
complex parsing code over arbitrary manual pages. If this
goes wrong for some reason unrelated to the content of the
page being displayed, you can set
$<b>MAN_DISABLE_SECCOMP</b> to any non-empty value to
disable the sandbox.</p>

<p style="margin-left:9%;"><b>PIPELINE_DEBUG</b></p>

<p style="margin-left:18%;">If the $<b>PIPELINE_DEBUG</b>
environment variable is set to &quot;1&quot;, then
<b>man</b> will print debugging messages to standard error
describing each subprocess it runs.</p>

<p style="margin-left:9%;"><b>LANG</b>,
<b>LC_MESSAGES</b></p>

<p style="margin-left:18%;">Depending on system and
implementation, either or both of $<b>LANG</b> and
$<b>LC_MESSAGES</b> will be interrogated for the current
message locale. <b>man</b> will display its messages in that
locale (if available). See <b>setlocale</b>(3) for precise
details.</p>
